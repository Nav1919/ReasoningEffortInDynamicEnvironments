# Stage A: reading the game state

We’re starting Stage A by preparing different ways to show the same Freeway situation to a model. We want to find out which format makes the game easier to read, and whether that changes with model size. This commit adds `freeway_observations.py`, which turns a saved observation into ASCII, coordinates, prose, a table, player-relative offsets or JSON. Each version includes every car’s ID, lane, position, direction, speed and length. The ASCII view also includes exact values so the grid doesn’t lose detail. Hidden timers, future positions and answer keys stay out of the inputs.

We’re using the existing bank of 500 situations from five development starts. These are related checkpoints, so we won’t treat them as 500 independent games. The original bank is unchanged. All nine relevant tests passed, all 500 situations rendered in all six formats with every car ID retained, and replay checks verified 9,369 saved action sequences. These are useful checks, but we still need stronger tests to confirm that every format preserves the same information. No model calls have been made, and we haven’t selected a winning format.

Next, we need to agree on how to measure things like distance and occupied cells, add questions with simulator-checked answers, and reserve unused starts for the final evaluation. We’ll also check which model sizes the hardware can handle and approve a run budget before inference. For now, this commit gives us a working preview tool and tests to build on. The commands, setup details and validation limits are in [the technical notes](stage-a-notes.md).
