# Offline freshness audit — proposed supporting interface

This is an offline descriptive audit, not an adopted freshness policy, evaluation
protocol, action-quality oracle, or change to the frozen model. Historical files
are read only and never relabeled. Human review is required before adoption.

## Task contract

- **Hypothesis:** supplied observation/tick records support independently checked
  observation-age and endpoint traffic-change measurements without new inference.
- **Dependencies:** baseline `22cdee9`, Python 3.13 standard library for the audit;
  existing integration tests use RealtimeGym
  `3d5b3ef37dafee25ca2e8d2e8d71f5fe842eda7b` and provisioned dependencies.
- **Acceptance:** hand-computed changed/unchanged cases, missing inputs, terminal
  cases, invalid clocks, CLI JSON/gzip behavior; both repository discovery suites.
- **Artifacts:** [implementation](../../freshness_audit.py),
  [tests](../../test_freshness_audit.py), this definition/results note, and JSON
  audit output generated by the command below (stdout, not historical evidence).
- **Seed/config manifest:** no generated games or sampling seeds. Inputs are the
  15 unchanged `evidence/freeway_20261008/live_*.json.gz` records covering saved
  environment seeds 0–4 and tick intervals 1/2/4 seconds. Their settings are not
  changed; checksums remain governed by `test_evidence_integrity.py`.
- **Compute allowance:** local CPU-only offline parsing/tests; no installs,
  downloads, network, paid experiments or model calls. Coding-assistant
  subscription authorized; token/cost telemetry is not available in this session.
- **Stop condition:** passing offline checks and a local tested commit for human
  review; no publishing, merging, scientific decisions or further experiments.

## Usage and input/output

From repository root:

```sh
/usr/bin/python3.13 freshness_audit.py evidence/freeway_20261008/live_*.json.gz > "$TMPDIR/freshness-audit-historical.json"
/usr/bin/python3.13 -m unittest test_freshness_audit -v
```

Or import `audit_episode(episode)`; this does not mutate its argument. The CLI
reads one or more plain/gzip JSON files and prints a JSON array. Each report
contains its source path, decision count, presence flags for `decisions`/`steps`,
per-metric missing counts, and decision rows with status, explicit action-tick
join availability, metrics and missing-metric names. Invalid records exit nonzero
with a source-specific error on stderr and no partial JSON on stdout.

The proposed input is the **existing native asynchronous runner format**, not a
migration to another schema. `decisions[].id` joins `steps[].decision_id` uniquely.
Each decision may supply `observed_turn`, `applied_turn`, `observed_seconds`,
`submitted_seconds`, `request_started_seconds`, `response_finished_seconds`,
`applied_seconds`, and `observation`. The joined step supplies `turn`,
`elapsed_seconds`, and `observation_before`. Times are finite nonnegative seconds
on the same monotonic episode-relative clock, not wall-clock date strings. The
audit cannot establish clock provenance from numbers alone.

Absent/null inputs yield null affected metrics, not zero. The report preserves
status (including failed-action fallback status) and does not exclude fallback
actions. No decisions in a file means zero audited decisions, not zero measured
age: presence flags distinguish a missing decisions field from an empty list.
Saved derived ages/latency are consistency checks only; they do not replace
missing source timestamps. An explicit application turn/time can support age
without a joined tick, but cannot support a traffic comparison.

## Definitions

Let `o` be supplied `observed_turn`, `a` be the action's **resulting** turn,
`t_o` the snapshot time, `t_r` request start, `t_f` response finish, and `t_a`
the action tick timestamp (before stepping the simulator).

| Output | Definition | Meaning |
|---|---|---|
| `observation_age_turns` | `a - 1 - o` | Completed world steps before action; excludes the action's own step |
| `observation_age_seconds` | `t_a - t_o` | Snapshot-to-action elapsed time |
| `pre_request_seconds` | `t_r - t_o` | Snapshot preparation/dispatch/worker-start delay |
| `inference_seconds` | `t_f - t_r` | Runner-measured request duration, not server token-generation time |
| `alignment_wait_seconds` | `t_a - t_f` | Response-finish-to-action wait, including collection/scheduling overhead |
| `traffic_changed` | Multisets of exposed car rows differ | Descriptive endpoint change, not harmful staleness |

When all timestamps exist, age seconds equals pre-request + inference + alignment
wait. This decomposition does not assume ideal ticks or multiply turns by a
configured interval. Supplied/application clocks and joined tick clocks must
agree within absolute `1e-8` seconds (only for duplicate/derived float checks).
Ordering is checked without tolerance. Present negative/nonfinite clocks, booleans,
non-integer turns, backward timing, inconsistent saved ages, mismatched turns,
duplicate IDs/applications, unknown joined IDs, steps after `done`, or application
fields on explicitly discarded/pending decisions are rejected. Partial ordered
clocks are checked even when an intermediate timestamp is missing. Tick order
must increase in turns and not decrease in seconds. No absent clock is imputed.

### Traffic comparison and worked examples

Use only `observation.state.car_states` and the joined pre-action
`observation_before.state.car_states` exposed in the saved observations. Each row
is `[lane, head_x, direction, speed, length]`. Compare **multisets** of complete
rows, ignoring row order but preserving duplicates. This is structured visible
traffic, including any off-board coordinates that the runner exposed, not a
raster-screen occupancy measure or a hidden-state simulator query. Player position,
rendered text, turn counters and outcomes do not enter the indicator. Coordinates
must be finite; head position may be negative. Missing traffic is unknown; two
explicit empty lists are known unchanged. No action-time observation is ever
reconstructed from a post-action/terminal observation.

1. Supplied at turn 1/time 1.0, request starts 1.2, finishes 2.5, action tick
   4/time 3.0: age is 2 turns/2.0 seconds; pre-request 0.2, inference 1.3,
   alignment 0.5 seconds. A supplied car `[1,0,"right",12,11]` versus
   pre-action `[1,24,"right",12,11]` gives `traffic_changed=true`.
2. Same clocks and the same car rows (even in a different list order), with a
   different player position or turn counter, give `traffic_changed=false`.
   Positive age alone does not establish changed endpoint traffic.

A true indicator does **not** show that the chosen action was wrong, that waiting
caused failure, or that refreshing would help. A false indicator does not show
that nothing happened between snapshots: traffic may wrap, reset after collision,
or return to the same endpoint. There are no optimal-action labels or thresholds.
Comparing complete exposed rows is intentionally simple, not a calibrated measure
of volatility, collision risk or consequential change.

Terminal transitions still use their pre-action observation even if the returned
observation is empty. `discarded_after_episode` and `pending_when_episode_ended`
retain any measured inference duration but have no application age/alignment or
traffic comparison. A late response never becomes an executed action.

## Read-only historical check (October 30, 2026)

The command above succeeded on all 15 saved live episodes: **982 decisions**,
**981 applied**, **1 discarded after episode**. Of the 981 supported pre-action
traffic comparisons, **221 changed** and **760 unchanged**. The discarded decision
has no application age in turns/seconds, no alignment wait and no traffic-change
value (one missing value in each of those four metrics). Pre-request and inference
durations exist for all 982 decisions. No missing decisions were replaced or
historical labels changed.

| Metric | Available | Observed range (rounded) |
|---|---:|---:|
| Age turns | 981 | 0–3 |
| Age seconds | 981 | 1.000051–6.007048 |
| Pre-request seconds | 982 | 0.000084–0.051580 |
| Inference seconds | 982 | 0.634307–5.138706 |
| Alignment wait seconds | 981 | 0.003010–3.297548 |

These are descriptive coverage/ranges in the preliminary pilot, not independent
samples or evidence for a causal/controller improvement. No held-out starts,
new model responses or other historical record types were analyzed.
